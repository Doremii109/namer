# Namer
Продвинутый ремапер, который также хорошо работает с областью видимости в функциях, классах и тд.

> Автор: **Doremi109** - https://github.com/Doremii109 <br>
> Ссылка на канал: https://t.me/doratools_channel

---

## Что делает

- **Переименование с учётом scope.** Отдельно отслеживает модульную область, функции (включая вложенные), аргументы, классы и их атрибуты. Корректно обрабатывает `global` / `nonlocal`, walrus (`:=`), `except ... as`, а также `match`-паттерны (`MatchAs`, `MatchStar`, `MatchMapping`).
- **Минификация вывода.** Патчит штатный `ast._Unparser` (на 3.14+ - `_ast_unparse.Unparser`), переписывая константы в его методах, чтобы `ast.unparse` убирал лишние пробелы и отступы (`", "` → `","`, `" = "` → `"="`, отступ в 4 пробела -> 1 и т.д.).
- **Сокрытие `__init__`.** Проход `skipInit` переименовывает `__init__` и прячет вызов либо через `locals().update(...)` (если у класса уже есть metaclass), либо через сгенерированный metaclass, чей `__call__` сам создаёт объект и зовёт переименованный инициализатор.
- **Ремап kwargs.** Keyword-аргументы в местах вызова переименовываются согласованно с сигнатурами функций и конструкторов (`__init__`).
- **Опциональный ремап builtins.** По флагу `built` ссылки на встроенные имена заменяются, а в начало добавляется шапка вида `_0xN,... = len,range,...`.

## Что НЕ трогает

- Магические имена (`__like_this__`) и методы `visit_*` (чтобы не ломать ast-код).
- `super`.
- Внешние атрибуты и kwargs: обращения к атрибутам не-`self`/не-`cls` объектов и keyword-аргументы вызовов нелокальных функций - они собираются в `pr_attr` автоматически на этапе `PreScan`.
- Любые имена из белых списков `pr_var` / `pr_attr`.

## Требования

- Python >= 3.10


## Использование

```python
from namer import rename

src = open("tester.py", encoding="utf8").read()
out = rename(src, track_instances=True)
open("tester_obf.py", "w", encoding="utf8").write(out)
```

Запуск модуля напрямую читает `DVM.py` и пишет результат в `OBFBBFFBFB.py` (см. блок `__main__`).

### API

```python
rename(code, built=False, track_instances=False)
```

| Параметр          | Тип                          | Назначение                                                                                              |
|-------------------|------------------------------|---------------------------------------------------------------------------------------------------------|
| `code`            | `str \| ast.Module`          | Исходник или AST. Для строки возвращается строка, для `ast.Module` - AST.                               |
| `built`           | `bool \| dict`               | `False` - не трогать builtins; `__builtins__` - ремапить их и добавить шапку с переназначениями.        |
| `track_instances` | `bool`                       | Ремапит атрибуты, доступные через `var = SomeClass(...)`. Осторожно: иногда ломает обфусцированный код. |

### Белые списки

Два модульных набора задают, что оставить нетронутым (заполняются вызывающей стороной до `rename`):

- `pr_var` - имена переменных/функций/классов, которые переименовывать нельзя;
- `pr_attr` - имена атрибутов, которые переименовывать нельзя (`PreScan` дополняет его найденными внешними атрибутами).

## Как это устроено
Всё происходит в функции `rename`:
1. **`PreScan`** - классифицирует имена: атрибуты классов (`cl_attr`), внешние атрибуты/kwargs (`pr_attr`), параметры `self`/`cls` по классам (`slf_n`), а при `track_instances` - локальные переменные-экземпляры (`inst_vars`).
2. **`CollectNames`** - проходит дерево со стеком областей видимости и назначает новые имена, запоминая карты аргументов (`args_mp`) и обфусцированные имена классов (`cls_obf`).
3. **`ReplNames`** - подставляет новые имена в местах использования (Load), резолвя их по стеку scope, и согласованно правит keyword-аргументы.
4. **`BuiltR`** (если задан `built`) - заменяет ссылки на builtins и формирует шапку.

`skipInit` применяется к дереву после `ReplNames`. Иначе он бы ломал `track_instances` если она включена.

## Ограничения

- **`track_instances`** - эвристика по конструкторам локальных классов; может ошибаться на нетривиальном коде.
